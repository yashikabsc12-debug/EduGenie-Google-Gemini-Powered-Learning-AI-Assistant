# EduGenie – Non Functional Requirements

## 1. Non Functional Requirements Overview

Non-functional requirements describe the quality, performance, usability, security, and reliability requirements of the EduGenie system.

## 2. Usability

The system should provide a simple and user-friendly interface so that students can easily access the learning features.

## 3. Performance

The system should process user requests and display the generated AI response within a reasonable time.

## 4. Reliability

The application should handle requests and errors properly without causing unnecessary application failures.

## 5. Scalability

The system should be designed so that additional learning features can be added in the future.

## 6. Security

The Gemini API key shall be stored securely using environment variables.

The API key shall not be exposed in frontend files or publicly shared through the GitHub repository.

## 7. Maintainability

The application should have a modular structure so that the backend, frontend, AI integration, and learning modules can be maintained separately.

## 8. Compatibility

The web application should be accessible through a modern web browser.

## 9. Accessibility

The interface should provide clear input areas, buttons, task selection, and readable results for students.

## 10. Resource Efficiency

EduGenie is designed with a lightweight web interface and backend so that it can be used without requiring high-end local hardware.

## 11. Extensibility

The system should support future enhancements such as multilingual support, voice interaction, progress tracking, gamification, and mobile application development.

## 12. Non Functional Requirement Summary

The system should be usable, reliable, secure, maintainable, scalable, and accessible while providing AI-powered educational assistance.
